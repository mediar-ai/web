# Tauri Specta - Type-Safe IPC

## Overview

**tauri-specta** automatically generates TypeScript types from your Rust Tauri commands, providing complete type safety between the Rust backend and TypeScript frontend.

## Installation

Already installed:
```toml
# src-tauri/Cargo.toml
specta = { version = "=2.0.0-rc.22", features = ["export", "derive"] }
tauri-specta = { version = "=2.0.0-rc.21", features = ["derive"] }
```

## How It Works

1. **Annotate Rust types** with `#[derive(specta::Type)]`
2. **Annotate commands** with `#[tauri::command]` and `#[specta::specta]`
3. **Generate TypeScript types** automatically
4. **Use types** in frontend with full type safety

## Setup

### Step 1: Create Type Generation Script

Create `src-tauri/src/commands.rs`:

```rust
use specta::Type;
use serde::{Serialize, Deserialize};

// ============================================================================
// Types with automatic TypeScript generation
// ============================================================================

#[derive(Debug, Clone, Serialize, Deserialize, Type)]
#[serde(rename_all = "camelCase")]
pub struct McpServerStatus {
    pub port: u16,
    pub is_running: bool,
    pub url: String,
    pub uptime_seconds: u64,
}

#[derive(Debug, Clone, Serialize, Deserialize, Type)]
#[serde(rename_all = "camelCase")]
pub struct WorkflowMcpServerStatus {
    pub port: u16,
    pub is_running: bool,
    pub uptime_seconds: u64,
}

// ============================================================================
// Type-safe Tauri commands
// ============================================================================

#[tauri::command]
#[specta::specta]
pub async fn get_mcp_server_info() -> Result<McpServerStatus, String> {
    let info = crate::mcp_server::get_mcp_server_info().await;

    Ok(McpServerStatus {
        port: info.port,
        is_running: info.is_running,
        url: info.url,
        uptime_seconds: info.uptime_seconds,
    })
}

#[tauri::command]
#[specta::specta]
pub async fn get_workflow_mcp_server_status() -> Result<WorkflowMcpServerStatus, String> {
    crate::workflow_mcp_server::get_workflow_mcp_server_status()
        .await
        .map(|status| WorkflowMcpServerStatus {
            port: status.port,
            is_running: status.is_running,
            uptime_seconds: status.uptime_seconds,
        })
        .map_err(|e| e.to_string())
}
```

### Step 2: Generate TypeScript Types

Create `src-tauri/src/lib.rs` type generation:

```rust
use tauri_specta::*;

pub mod commands;

#[cfg(debug_assertions)]
pub fn generate_typescript_types() {
    ts::export(
        collect_commands![
            commands::get_mcp_server_info,
            commands::get_workflow_mcp_server_status,
        ],
        "../src/lib/bindings.ts",
    )
    .unwrap();
}
```

### Step 3: Generate Types on Build

Add to `src-tauri/src/main.rs`:

```rust
fn main() {
    // Generate TypeScript types in development
    #[cfg(debug_assertions)]
    mediar_lib::generate_typescript_types();

    tauri::Builder::default()
        // ... rest of your setup
        .invoke_handler(tauri::generate_handler![
            mediar_lib::commands::get_mcp_server_info,
            mediar_lib::commands::get_workflow_mcp_server_status,
            // ... other commands
        ])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

### Step 4: Use Generated Types in Frontend

The generated `src/lib/bindings.ts` will contain:

```typescript
// Auto-generated by tauri-specta
export type McpServerStatus = {
  port: number;
  isRunning: boolean;
  url: string;
  uptimeSeconds: number;
};

export type WorkflowMcpServerStatus = {
  port: number;
  isRunning: boolean;
  uptimeSeconds: number;
};

// Type-safe command wrappers
export async function getMcpServerInfo(): Promise<Result<McpServerStatus, string>> {
  return await invoke('get_mcp_server_info');
}

export async function getWorkflowMcpServerStatus(): Promise<Result<WorkflowMcpServerStatus, string>> {
  return await invoke('get_workflow_mcp_server_status');
}
```

Use in your components:

```typescript
import { getMcpServerInfo, type McpServerStatus } from '@/lib/bindings';

async function checkServer() {
  // Fully typed!
  const status: McpServerStatus = await getMcpServerInfo();
  console.log(`Server on port ${status.port} is ${status.isRunning ? 'up' : 'down'}`);
}
```

## Benefits

### 1. **Automatic Type Sync**

```rust
// Change in Rust
pub struct McpServerStatus {
    pub port: u16,
    pub is_running: bool,
    pub new_field: String,  // Added field
}
```

TypeScript automatically gets the new field:
```typescript
// TypeScript knows about new_field!
const status = await getMcpServerInfo();
console.log(status.newField);  // Autocomplete works!
```

### 2. **Compile-Time Safety**

```typescript
// ❌ TypeScript error - field doesn't exist in Rust
const invalid = await getMcpServerInfo();
console.log(invalid.nonExistentField);  // Error!

// ✅ Correct - field exists in Rust
console.log(invalid.port);  // Works!
```

### 3. **Zero Manual Maintenance**

No need to manually write:
- TypeScript interfaces
- Zod schemas (for these specific types)
- Type conversions

Types are generated automatically from Rust source of truth.

## Advanced Features

### Complex Types

```rust
#[derive(Serialize, Deserialize, Type)]
pub enum WorkflowStatus {
    Pending,
    Running { step: usize, total: usize },
    Completed { duration_ms: u64 },
    Failed { error: String },
}

#[derive(Serialize, Deserialize, Type)]
pub struct Workflow {
    pub id: String,
    pub name: String,
    pub status: WorkflowStatus,
    pub steps: Vec<WorkflowStep>,
    pub metadata: HashMap<String, String>,
}
```

Generates TypeScript:
```typescript
export type WorkflowStatus =
  | { type: "Pending" }
  | { type: "Running"; step: number; total: number }
  | { type: "Completed"; durationMs: number }
  | { type: "Failed"; error: string };

export type Workflow = {
  id: string;
  name: string;
  status: WorkflowStatus;
  steps: WorkflowStep[];
  metadata: Record<string, string>;
};
```

### Optional Fields

```rust
#[derive(Serialize, Deserialize, Type)]
pub struct User {
    pub id: String,
    pub email: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub name: Option<String>,  // Optional in both Rust and TS
}
```

Generates:
```typescript
export type User = {
  id: string;
  email: string;
  name?: string;  // Optional in TypeScript too!
};
```

### Rename Fields

```rust
#[derive(Serialize, Deserialize, Type)]
#[serde(rename_all = "camelCase")]  // snake_case → camelCase
pub struct Config {
    pub api_key: String,        // → apiKey
    pub max_retries: u32,       // → maxRetries
    pub enable_logging: bool,   // → enableLogging
}
```

## Workflow

### Development Workflow

1. **Write Rust types** with `#[derive(Type)]`
2. **Add command** with `#[tauri::command]` and `#[specta::specta]`
3. **Run `tauri dev`** - types are auto-generated
4. **Use in TypeScript** - full autocomplete and type checking!

### Build Process

```bash
# Development - generates types
bun run dev:tauri

# Production - no type generation overhead
bun run build:tauri
```

## Comparison: Manual vs Specta

### Manual Approach (Current)

**Rust**:
```rust
#[tauri::command]
pub async fn get_server_status() -> Result<String, String> {
    // Return JSON string
    Ok(serde_json::to_string(&status).unwrap())
}
```

**TypeScript**:
```typescript
// Manual interface (can drift from Rust)
interface ServerStatus {
  port: number;
  isRunning: boolean;
}

// Manual Zod schema
const ServerStatusSchema = z.object({
  port: z.number(),
  isRunning: z.boolean(),
});

// Manual validation
const response = await invoke('get_server_status');
const status = ServerStatusSchema.parse(JSON.parse(response));
```

**Problems**:
- 3 places to update (Rust, TS interface, Zod schema)
- Types can drift out of sync
- Manual validation needed
- More code to maintain

### Specta Approach (Recommended)

**Rust**:
```rust
#[derive(Serialize, Deserialize, Type)]
pub struct ServerStatus {
    pub port: u16,
    pub is_running: bool,
}

#[tauri::command]
#[specta::specta]
pub async fn get_server_status() -> Result<ServerStatus, String> {
    Ok(status)
}
```

**TypeScript**:
```typescript
// Auto-generated, always in sync!
import { getServerStatus } from '@/lib/bindings';

const status = await getServerStatus();  // Fully typed!
```

**Benefits**:
- ✅ Single source of truth (Rust)
- ✅ Types automatically synced
- ✅ No manual validation needed (Tauri handles it)
- ✅ Less code to maintain
- ✅ Compile-time guarantees

## When to Use What

### Use Tauri-Specta for:
- ✅ Tauri command types (inputs/outputs)
- ✅ Simple data structures
- ✅ Server status/info types
- ✅ Configuration types

### Still Use Zod for:
- ✅ External API responses (not from Tauri)
- ✅ MCP server responses (external protocol)
- ✅ User input validation
- ✅ Complex runtime validation logic
